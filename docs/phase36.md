# Phase 36：真实浏览器供应商链路验收

完成日期：2026-09-28。

## 完成内容

使用 Playwright Chromium 从首页实际填写并提交西安 3 天请求：2026-09-28 至 2026-09-30、公共交通、经济型酒店、历史文化与购物、预算 3000 元、每日步行 6 公里、单段交通 60 分钟，并明确保持“仅安排无需预约景点”未勾选。

请求经过真实高德检索、天气、公交路线和已配置 LLM，后端记录 `stream.completed`，单次耗时 115578 ms。浏览器进入 `/result`，显示 3 个日期页签、景点到访时间、住宿、餐饮、天气和预算。本次是一个固定案例的验收结果，不代表线上成功率或性能基准。

前端表单现在显式初始化 `avoid_reservation_required: false`，避免未勾选时依赖 JSON 省略字段和后端默认值。新增 `TRIPPILOT_LIVE_E2E=1` 才启用的真实端到端用例；普通回归默认跳过它，避免 CI 消耗供应商额度。

## 边界与遗留问题

- 这只是一次西安固定案例，不能推导成功率、P50/P95、token 或成本。
- Playwright 验收环境没有注入高德 JS 地图 Key，因此结果页地图组件提示加载失败；行程 API、POI 坐标、路线、天气和结果展示已经完成。
- 官方证据仍只覆盖故宫有限语料；西安景点显示证据缺失 warning，不能宣称营业和预约事实已核验。
- 真实用例默认不进入 CI；运行它需要本地供应商凭据并会产生实际调用。

## 下一阶段建议

扩大带官方来源的景区证据和固定真实案例集，并单独记录逐例约束满足与失败类型；不要把单例通过包装为全链路性能或成功率。
